# PV Abandoned Cart — 1С-Битрикс (v1.0.3)

## Установка
Распакуйте `pv.abandonedcart` в `/local/modules/` (или `/bitrix/modules/`).
В админке установите модуль через Marketplace → Установленные решения.
Административная страница: `/bitrix/admin/pv_abandonedcart_list.php`.

## Обновление установленной v1.0.0 на тестовом сайте
1. Сохраните резервную копию файлов модуля и БД.
2. Замените **всю** папку `/local/modules/pv.abandonedcart/` содержимым новой версии.
3. Скопируйте `install/admin/pv_abandonedcart_list.php` в `/bitrix/admin/pv_abandonedcart_list.php` (перезапишите старый файл).
4. Откройте административную страницу. Не нужно удалять модуль и таблицу БД.
5. Проверьте создание тестовой корзины, её обновление, оформление заказа и переход в abandoned после тайм-аута.

## Исправления v1.0.1
- Административная точка входа ищет модуль в `/local/modules` и `/bitrix/modules`.
- Установщик копирует правильный файл `install/admin/pv_abandonedcart_list.php`.
- Безопасная проверка текущего пользователя и корзины заказа.
- Повторная установка не сбрасывает пользовательские настройки времени.
- Отсутствующая таблица показывает понятное сообщение вместо SQL-исключения.

## Ограничения
- В версии 1.0.3 контакты стандартного `sale.order.ajax` собираются по ID свойств заказа и их настройкам в Битрикс. Для нестандартного checkout доступен серверный `Tracker::saveContact`.
- Отслеживание через события зависит от используемого шаблона и API сохранения корзины; требуется живой тест.
- Агент выполняется по расписанию Битрикс, при стандартном режиме — во время посещений сайта.
- Текущая таблица хранит одну запись на FUSER_ID + SITE_ID, а не историю всех корзин.
- Суммы разных валют в статистике не конвертируются.
- При удалении модуля данные таблицы намеренно сохраняются.
- Это тестовая сборка, а не проверенная модерацией Marketplace версия.

## Обновление 1.0.2 (тестовая версия)

1. Сделайте резервную копию файлов модуля и базы данных.
2. Замените каталог `/local/modules/pv.abandonedcart/` на содержимое архива.
3. В админке `/bitrix/admin/pv_abandonedcart_list.php` нажмите «Применить обновление 1.0.2» один раз. Это добавит колонки и зарегистрирует обработчик подключения JavaScript. Удалять модуль не нужно.
4. Проверьте работу на стандартной странице `sale.order.ajax` с тестовыми персональными данными. Нужна активная корзина.
5. Перед использованием на реальном сайте настройте уведомление и согласие на обработку персональных данных; код пытается уважать типовые флажки согласия, но не может гарантировать соответствие индивидуальной форме.

Ограничения версии 1.0.2 (исправления ниже): автоматическое распознавание полей выполняется по именам/id/placeholder и может не сработать с числовыми именами свойств заказа стандартного компонента. Не является гарантированно универсальной интеграцией; проверяйте Network в браузере и тестируйте каждую конфигурацию. Стоимость доставки, человекочитаемые названия способов доставки и оплаты, свойства SKU пока не реализованы. В обработчик не передаются данные банковских карт.


## Версия 1.0.3

- Стандартные поля `ORDER_PROP_<ID>` сопоставляются с настройками свойств заказа: ФИО, email и телефон определяются по флагам Битрикс и стандартным кодам свойств. ID свойств не зашиты в модуль.
- Код местоположения преобразуется в название населённого пункта; индекс и адрес сохраняются вместе с ним. Для этого свойство должно иметь тип «Местоположение» / флаг местоположения. Если выбран только регион, будет показан регион.
- Доставка и оплата сохраняются с названиями из справочников Битрикс. Старые числовые значения также расшифровываются при просмотре; для удалённых способов остаётся ID.
- Сбор запускается для уже заполненной формы и после AJAX-обновлений checkout. Ответ `ok:false` больше не считается успешным сохранением.
- Сохранены проверка сессии, проверка согласия, экранирование вывода и запрет перезаписи оформленных заказов. Поля карт и паролей исключаются из сбора.
- Скрипт и endpoint поддерживают установку как в `/local/modules`, так и в `/bitrix/modules`; версия в URL скрипта обновлена для сброса кеша.

### Обновление с 1.0.2

1. Сделайте резервную копию каталога модуля и базы тестового сайта.
2. Замените файлы в существующем каталоге `pv.abandonedcart` файлами новой версии. Не удаляйте модуль и таблицу.
3. Скопируйте `install/admin/pv_abandonedcart_list.php` в `/bitrix/admin/pv_abandonedcart_list.php`, если используете старую точку входа.
4. В административной странице нажмите «Применить обновление 1.0.3». Обновление добавляет недостающие колонки без очистки данных; при повторном запуске уже существующие колонки не добавляются.
5. Очистите кеш Битрикс и перезагрузите страницу оформления. Создайте новую тестовую корзину, заполните ФИО, телефон, email, город и адрес; выберите доставку и оплату и дайте согласие на обработку данных. Убедитесь в Network, что `capture.php` возвращает `{"ok":true}`, затем проверьте данные в админке. Повторите после изменения доставки и AJAX-перерисовки формы, а также с неотмеченным согласием.

Ранее не сохранённые контакты и город восстановить из старой записи невозможно: они появятся после повторного заполнения/открытия checkout покупателем. Расшифровка старых ID доставки и оплаты доступна сразу.

Нестандартные шаблоны и пользовательские названия/коды свойств требуют отдельной проверки. Стоимость доставки, характеристики SKU и восстановление ранее утраченных данных в эту версию не входят. Проверки ниже изолированные; проверка на реальном ядре Битрикс необходима перед установкой на рабочий магазин.

### Проверки разработчика

```bash
php tests/checkout.php
# jsdom — только зависимость тестов; устанавливается вне checkout:
npm install --prefix /tmp/pv-abandonedcart-tests --cache /tmp/pv-abandonedcart-npm --no-audit --no-fund jsdom@26
NODE_PATH=/tmp/pv-abandonedcart-tests/node_modules node --test tests/checkout.js
```

PHP-проверки используют тестовые адаптеры API Битрикс: числовые свойства, контакты, город/адрес, названия способов, старые ID, неверный ввод и защита оформленных заказов. JavaScript-проверки выполняют скрипт в jsdom: стандартная форма, скрытый код местоположения, исключение карточных полей, предзаполнение, AJAX, согласие и повтор после неуспешного сохранения.
