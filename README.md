# PV Abandoned Cart — 1С-Битрикс (v1.0.5)

## Установка
Распакуйте `pv.abandonedcart` в `/local/modules/` (или `/bitrix/modules/`).
В админке установите модуль через Marketplace → Установленные решения.
Административная страница: `/bitrix/admin/pv_abandonedcart_list.php`.

## Обновление установленной v1.0.0 на тестовом сайте
1. Сохраните резервную копию файлов модуля и БД.
2. Замените **всю** папку `/local/modules/pv.abandonedcart/` содержимым новой версии.
3. Скопируйте `install/admin/pv_abandonedcart_list.php` в `/bitrix/admin/pv_abandonedcart_list.php` (перезапишите старый файл).
4. Откройте административную страницу. Не нужно удалять модуль и таблицу БД.
5. Проверьте создание тестовой корзины, её обновление, оформление заказа и переход в abandoned после тайм-аута.

## Исправления v1.0.1
- Административная точка входа ищет модуль в `/local/modules` и `/bitrix/modules`.
- Установщик копирует правильный файл `install/admin/pv_abandonedcart_list.php`.
- Безопасная проверка текущего пользователя и корзины заказа.
- Повторная установка не сбрасывает пользовательские настройки времени.
- Отсутствующая таблица показывает понятное сообщение вместо SQL-исключения.

## Ограничения
- В версии 1.0.3 контакты стандартного `sale.order.ajax` собираются по ID свойств заказа и их настройкам в Битрикс. Для нестандартного checkout доступен серверный `Tracker::saveContact`.
- Отслеживание через события зависит от используемого шаблона и API сохранения корзины; требуется живой тест.
- Агент выполняется по расписанию Битрикс, при стандартном режиме — во время посещений сайта.
- Текущая таблица хранит одну запись на FUSER_ID + SITE_ID, а не историю всех корзин.
- Суммы разных валют в статистике не конвертируются.
- При удалении модуля данные таблицы намеренно сохраняются.
- Это тестовая сборка, а не проверенная модерацией Marketplace версия.

## Обновление 1.0.2 (тестовая версия)

3. В админке `/bitrix/admin/pv_abandonedcart_list.php` нажмите «Применить обновление 1.0.2» один раз. Это добавит колонки и зарегистрирует обработчик подключения JavaScript. Удалять модуль не нужно.

5. Перед использованием на реальном сайте настройте уведомление и согласие на обработку персональных данных; код пытается уважать типовые флажки согласия, но не может гарантировать соответствие индивидуальной форме.

Ограничения версии 1.0.2 (исправления ниже): автоматическое распознавание полей выполняется по именам/id/placeholder и может не сработать с числовыми именами свойств заказа стандартного компонента. Не является гарантированно универсальной интеграцией; проверяйте Network в браузере и тестируйте каждую конфигурацию. Стоимость доставки, человекочитаемые названия способов доставки и оплаты, свойства SKU пока не реализованы. В обработчик не передаются данные банковских карт.


## Версия 1.0.3

- Стандартные поля `ORDER_PROP_<ID>` сопоставляются с настройками свойств заказа: ФИО, email и телефон определяются по флагам Битрикс и стандартным кодам свойств. ID свойств не зашиты в модуль.
- Код местоположения преобразуется в название населённого пункта; индекс и адрес сохраняются вместе с ним. Для этого свойство должно иметь тип «Местоположение» / флаг местоположения. Если выбран только регион, будет показан регион.
- Доставка и оплата сохраняются с названиями из справочников Битрикс. Старые числовые значения также расшифровываются при просмотре; для удалённых способов остаётся ID.
- Сбор запускается для уже заполненной формы и после AJAX-обновлений checkout. Ответ `ok:false` больше не считается успешным сохранением.
- Сохранены проверка сессии, проверка согласия, экранирование вывода и запрет перезаписи оформленных заказов. Поля карт и паролей исключаются из сбора.
- Скрипт и endpoint поддерживают установку как в `/local/modules`, так и в `/bitrix/modules`; версия в URL скрипта обновлена для сброса кеша.

### Обновление с 1.0.2

1. Сделайте резервную копию каталога модуля и базы тестового сайта.
2. Замените файлы в существующем каталоге `pv.abandonedcart` файлами новой версии. Не удаляйте модуль и таблицу.
3. Скопируйте `install/admin/pv_abandonedcart_list.php` в `/bitrix/admin/pv_abandonedcart_list.php`, если используете старую точку входа.
4. В административной странице нажмите «Применить обновление 1.0.3». Обновление добавляет недостающие колонки без очистки данных; при повторном запуске уже существующие колонки не добавляются.
5. Очистите кеш Битрикс и перезагрузите страницу оформления. Создайте новую тестовую корзину, заполните ФИО, телефон, email, город и адрес; выберите доставку и оплату и дайте согласие на обработку данных. Убедитесь в Network, что `capture.php` возвращает `{"ok":true}`, затем проверьте данные в админке. Повторите после изменения доставки и AJAX-перерисовки формы, а также с неотмеченным согласием.

Ранее не сохранённые контакты и город восстановить из старой записи невозможно: они появятся после повторного заполнения/открытия checkout покупателем. Расшифровка старых ID доставки и оплаты доступна сразу.

Нестандартные шаблоны и пользовательские названия/коды свойств требуют отдельной проверки. Стоимость доставки, характеристики SKU и восстановление ранее утраченных данных в эту версию не входят. Проверки ниже изолированные; проверка на реальном ядре Битрикс необходима перед установкой на рабочий магазин.

### Проверки разработчика

```bash
php tests/checkout.php
# jsdom — только зависимость тестов; устанавливается вне checkout:
npm install --prefix /tmp/pv-abandonedcart-tests --cache /tmp/pv-abandonedcart-npm --no-audit --no-fund jsdom@26
NODE_PATH=/tmp/pv-abandonedcart-tests/node_modules node --test tests/checkout.js
```

PHP-проверки используют тестовые адаптеры API Битрикс: числовые свойства, контакты, город/адрес, названия способов, старые ID, неверный ввод и защита оформленных заказов. JavaScript-проверки выполняют скрипт в jsdom: стандартная форма, скрытый код местоположения, исключение карточных полей, предзаполнение, AJAX, согласие и повтор после неуспешного сохранения.


## Версия 1.0.4 — синхронизация корзины и checkout

- URL обработчика и сайт задаются сервером: путь больше не выводится из адреса объединённого JS-файла кеша Битрикс. Это устраняет ошибочную отправку в `/bitrix/cache/.../tools/capture.php`.
- Изменения формы отправляются с задержкой 900 мс. Каждые 5 секунд проверяются изменения, включая автозаполнение и перерисовку без событий. Неизменённые данные повторно не отправляются. После ошибки выполняются повторные попытки с интервалом от 5 до 60 секунд; зависший запрос прерывается через 15 секунд.
- Запросы выполняются последовательно: если покупатель дополнил форму во время отправки, следующий запрос берёт её актуальное состояние. Поля, временно отсутствующие при AJAX-перерисовке, сохраняются в снимке свойств; явная очистка присутствующего поля передаётся как пустое значение.
- Если корзина появилась до установки модуля и ещё не зарегистрирована событием, запись создаётся из реальной корзины покупателя при отправке формы. Без товаров новая запись с одними контактами не создаётся.
- Дополнение брошенной корзины переводит её обратно в активную. Событие сохранения корзины оформленного заказа и редактирование старого заказа не должны менять статус текущей покупательской корзины. При новой корзине после завершённого заказа старые контакты и данные оформления очищаются.
- Админка обновляет список и статистику каждые 10 секунд без перезагрузки страницы и без сброса редактируемых настроек. Показывается отдельное время последнего получения данных формы. Статусы, владелец корзины и отсутствие оформленного заказа подписаны по-русски.

### Как определяется корзина

Ключ записи — `FUSER_ID + SITE_ID`, а не HTTP-сессия, email или номер заказа. `FUSER_ID` — внутренний идентификатор владельца корзины в Битрикс; он не является ID учётной записи. Пока этот ключ прежний, дополнение формы и изменение товаров обновляют ту же запись. Другой браузер, очищенные cookies или смена владельца корзины при авторизации могут дать другой FUSER. Модуль не объединяет посетителей по введённым контактам.

Колонка «Оформленный заказ» содержит ID реально сохранённого заказа. Пока покупатель не завершил оформление, показывается «Ещё не оформлен». Текущая схема по-прежнему хранит одну последнюю корзину на владельца и сайт: при новой корзине после заказа строка используется заново, отдельной истории всех заказов здесь нет.

Контакты поступают только из открытой формы checkout и при разрешённом сборе (отмеченных найденных флажках согласия). При отсутствии связи синхронизация возобновляется, пока страница открыта; сохранение последних изменений при немедленном закрытии вкладки не гарантируется. Админка показывает последнюю серверную копию, задержка появления обычных изменений — примерно до 15 секунд при работающем соединении. Старые потерянные данные восстановить автоматически нельзя.

### Обновление на 1.0.4

1. Сделайте резервную копию файлов модуля и БД, сначала используйте тестовый сайт.
2. Замените файлы установленного `pv.abandonedcart`, не удаляя модуль и таблицу.
3. В админке нажмите **«Применить обновление 1.0.4»**. Это обязательно: добавляются `CHECKOUT_DATA` (снимок распознанных свойств) и `CHECKOUT_UPDATED_AT` (время получения формы). Повторное применение не удаляет данные и не добавляет колонки повторно.
4. Очистите кеш Битрикс, включая объединённые JS, и перезагрузите checkout и административную страницу.
5. На тестовой корзине заполните данные и дайте согласие; не оформляя заказ, измените телефон, адрес, доставку и оплату. Убедитесь, что та же строка в админке меняется без ручного обновления. Повторите с объединением JS, AJAX-перерисовкой, автозаполнением и кратковременным отключением сети.
6. Проверьте оформление: номер заказа должен появиться только после сохранения. При последующем добавлении товаров новая корзина не должна наследовать контакты прежнего заказа.

Дополнительная проверка интерфейса админки (те же временные jsdom-зависимости, что выше):

```bash
NODE_PATH=/tmp/pv-abandonedcart-tests/node_modules node --test tests/checkout.js tests/admin.js
```

Если PHP отсутствует в PATH, задайте `PHP_BIN=/полный/путь/php` для теста админки. Тесты используют адаптеры Битрикс, реального ядра и БД в них нет. Проверка на тестовом сайте перед использованием в рабочем магазине остаётся необходимой.


## Версия 1.0.5 — компактная админка и ручная очистка

- Основная строка содержит статус, покупателя, краткий состав корзины, сумму и время обновления. Стрелка раскрывает полный состав, контакты, адрес, комментарий, доставку, оплату и оформленный заказ. Строка с FUSER и сайтом убрана.
- Выберите записи галочками и нажмите «Удалить выбранные». Галочка в заголовке выбирает только показанные строки текущего фильтра (максимум 200), а не всю базу. Перед удалением запрашивается подтверждение.
- Удаляются только записи таблицы модуля `pv_abandoned_cart`, включая сохранённые контакты и снимок формы. Корзины, товары, аккаунты и заказы Битрикс не удаляются. Если покупатель продолжит работу с действующей корзиной, новая активность может снова создать запись отслеживания.
- Действие удаления доступно администратору, выполняется только POST-запросом с корректной сессией Битрикс и проверенным списком ID. Оно не меняет настройки хранения. После удаления пересчитываются счётчики и суммы.
- Общий счётчик брошенных корзин учитывает все записи со статусом `abandoned` вне зависимости от выбранного фильтра и ограничения в 200 строк. Суммы брошенных корзин показаны отдельно по валютам. Рядом отображается общее число записей, включая активные и оформленные.
- Автообновление сохраняет выбранные галочки и раскрытые строки. Новые поступившие строки автоматически не выбираются. Настройки и обновление модуля свёрнуты в отдельный блок.

Для обновления замените файлы модуля, очистите кеш Битрикс и перезагрузите административную страницу. Для установки поверх 1.0.4 новых колонок БД нет. Если обновляетесь с более старой версии, откройте «Настройки и обновление модуля» и нажмите «Применить обновление 1.0.5».

Проверки админки включают раскрытие строк, сохранение выбора при автообновлении, выбор всех показанных записей, удаление только выбранных записей, защиту сессии и прав, некорректные ID, общий счётчик вне фильтра и раздельные суммы по валютам. Команды проверки остаются теми же, что выше.
